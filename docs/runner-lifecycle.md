# 执行端管理任务生命周期

v0.10.0 开始，公司员工只负责完成任务和输出工作结果。领取、续租、状态同步、提交送审、评审入库及失败重试由执行端完成。Paseo 与原生 CLI 使用相同的收尾逻辑。

## 工作输出

执行岗在最终答复中给出成果、验证和产物位置，然后结束本轮。执行端自动送审。工作确实受阻时，首行写 `工作结果：受阻`，正文说明缺口。

复核岗在最终答复首行明确写 `复核结论：通过` 或 `复核结论：退回`，随后给出独立验收证据。结束事件只触发收集，不代替独立复核或已有验收门禁。

可选的 `result.json` 只承载工作数据：`summary`、`outcome`（completed/blocked）、`review`（accept/return）、`sha`、`environment`。任务号、租约、版本、幂等键由执行端提供，文件中同名字段不会被使用。普通任务无需写此文件。

代码任务优先使用成果中明确声明的 SHA；缺省时从登记的工作树读取 HEAD。发布环境来自任务的已授权配置。CI、SHA、部署证据与独立评审门禁保持生效。

## 状态与持久化

- 派工前原子领取，建立 reserved 执行批次，防止重复分配。
- 收到宿主的实际 turn_started 后记录 running。任务业务阶段 doing 覆盖已分配的工作，老板端另行显示真实执行状态。
- 正常回合结束先将原始最终答复和业务结果写入节点私有执行日志，再调用任务核心送审或记录评审。
- 未完成/取消的回合记录 interrupted，不能把残留报告当作成功结果。
- 写库失败保留结果和租约，按现有派工循环退避重试。未知提交结果重放同一份 proof 与幂等键；明确版本冲突才重新核对并更新版本。
- 已记录的旧回合不能提交新批次。原生 CLI 还持久保存尚未交付的结束事件，重启时只重放事件。
- 持续的确定性验收拒绝会保存原成果并转为阻塞；基础设施错误由执行端处理，员工不承担协议排障。

节点私有日志位于 comm 根的同级 `private/executions/<comm-root-hash>/`，员工沙箱不可读。每个 delivery 独立文件，结果采用临时文件、fsync 和原子 rename 保存。节点重启可恢复；跨机器仍需公司任务记录和工作产物交接，不共享原生会话文件。

任务的 `runtime_execution` 保存供老板端查看的状态、回合关联、重试次数和安全错误类别，不包含原始供应商输出或凭证。

## 工作工具与兼容

员工目录保留资料查询、授权账号/登录态、带登录链接、浏览器、远程命令和供应商能力。任务创建、改派、撤回、审批及消息放行只能由老板或执行端操作。

旧会话的 submit/review/report_blocker 调用仅保存工作成果，不立即改变任务状态；回复告知员工结束本轮即可。checkpoint/heartbeat 不再要求员工维护。真正的状态变更仍由结束事件驱动。

schema 064 精确替换已知默认派工模板，清除相应过期译文；不修改已发消息或老板编辑的正文。旧定制正文暂通过上述兼容入口收尾。

## 验证与回退

新增测试覆盖真实 fork 上从执行到独立验收、结果重放、失联、重启、版本竞争、旧回合隔离和模板迁移。

发布顺序：CI → schema 064 → 老板端 Worker → 节点插件更新 → 生产只读任务验证。生产验收要求 submit 和 accept 来自执行端，执行会话无需生命周期命令，最终任务进入 done。

回退前暂停派工并排空 pending 结果；保留私有执行日志。旧版不认识自动输出协议，回退插件时必须同步恢复对应派工模板，不能只切换二进制。

## Paseo 0.15 兼容

v0.10.1 修复生产验收发现的空事件问题：宿主 `agent.turn.after` 总是传入空 timeline。执行端按 agent ID 和 turn ID 读取持久时间线，只接受该回合最后一条最终答复；读取失败保留 collecting 并重试，不把基础设施问题变成业务阻塞。原生执行器仍直接提供本轮结果。

v0.10.2 同时处理宿主刷新后复用回合编号的情况：启动与去重按 delivery 保存，持久时间线还需晚于本批次启动，并确认宿主不再处于活动回合。schema 064 执行成功后记录完成回执。
