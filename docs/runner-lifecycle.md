# 执行端管理任务生命周期

v0.10.0 开始，公司员工只负责完成任务和输出工作结果。领取、续租、状态同步、提交送审、评审入库及失败重试由执行端完成。Paseo 与原生 CLI 使用相同的收尾逻辑。

## 工作输出

执行岗在最终答复中给出成果、验证和产物位置，然后结束本轮。执行端自动送审。工作确实受阻时，首行写 `工作结果：受阻`，正文说明缺口。

复核岗在最终答复首行明确写 `复核结论：通过` 或 `复核结论：退回`，随后给出独立验收证据。结束事件只触发收集，不代替独立复核或已有验收门禁。

可选的 `result.json` 只承载工作数据：`summary`、`outcome`（completed/blocked）、`review`（accept/return）、`sha`、`environment`。任务号、租约、版本、幂等键由执行端提供，文件中同名字段不会被使用。普通任务无需写此文件。

代码任务优先使用成果中明确声明的 SHA；结构化成果（result.json/report.md）缺省时从登记的工作树读取 HEAD。任何运行时文本答复（宿主时间线读出或结束事件携带）不适用 HEAD 补齐：没有声明 `提交：<40位SHA>` 或 `工作结果：受阻` 首行的消息是进度，不是交付。发布环境来自任务的已授权配置。CI、SHA、部署证据与独立评审门禁保持生效。

## 状态与持久化

- 派工前原子领取，建立 reserved 执行批次，防止重复分配。
- 收到宿主的实际 turn_started 后记录 running。任务业务阶段 doing 覆盖已分配的工作，老板端另行显示真实执行状态。
- 正常回合结束先将原始最终答复和业务结果写入节点私有执行日志，再调用任务核心送审或记录评审。
- 未完成/取消的回合记录 interrupted，不能把残留报告当作成功结果。
- 写库失败保留结果和租约，按现有派工循环退避重试。未知提交结果重放同一份 proof 与幂等键；明确版本冲突才重新核对并更新版本。
- 已记录的旧回合不能提交新批次。原生 CLI 还持久保存尚未交付的结束事件，重启时只重放事件。
- 持续的确定性验收拒绝会保存原成果并转为阻塞；基础设施错误由执行端处理，员工不承担协议排障。

节点私有日志位于 comm 根的同级 `private/executions/<comm-root-hash>/`，员工沙箱不可读。每个 delivery 独立文件，结果采用临时文件、fsync 和原子 rename 保存。节点重启可恢复；跨机器仍需公司任务记录和工作产物交接，不共享原生会话文件。

任务的 `runtime_execution` 保存供老板端查看的状态、回合关联、重试次数和安全错误类别，不包含原始供应商输出或凭证。

## 工作工具与兼容

员工目录保留资料查询、授权账号/登录态、带登录链接、浏览器、远程命令和供应商能力。任务创建、改派、撤回、审批及消息放行只能由老板或执行端操作。

旧会话的 submit/review/report_blocker 调用仅保存工作成果，不立即改变任务状态；回复告知员工结束本轮即可。checkpoint/heartbeat 不再要求员工维护。真正的状态变更仍由结束事件驱动。

schema 064 精确替换已知默认派工模板，清除相应过期译文；不修改已发消息或老板编辑的正文。旧定制正文暂通过上述兼容入口收尾。

## 验证与回退

新增测试覆盖真实 fork 上从执行到独立验收、结果重放、失联、重启、版本竞争、旧回合隔离和模板迁移。

发布顺序：CI → schema 064 → 老板端 Worker → 节点插件更新 → 生产只读任务验证。生产验收要求 submit 和 accept 来自执行端，执行会话无需生命周期命令，最终任务进入 done。

回退前暂停派工并排空 pending 结果；保留私有执行日志。旧版不认识自动输出协议，回退插件时必须同步恢复对应派工模板，不能只切换二进制。

## Paseo 0.15 兼容

v0.10.1 修复生产验收发现的空事件问题：宿主 `agent.turn.after` 总是传入空 timeline。执行端按 agent ID 和 turn ID 读取持久时间线，只接受该回合最后一条最终答复；读取失败保留 collecting 并重试，不把基础设施问题变成业务阻塞；v0.13.28 起重试有界，见下文。原生执行器仍直接提供本轮结果。

v0.10.2 同时处理宿主刷新后复用回合编号的情况：启动与去重按 delivery 保存，持久时间线还需晚于本批次启动，并确认宿主不再处于活动回合。schema 064 执行成功后记录完成回执。

## v0.11.5 租约监督

超时只触发停止请求，不构成重新派工的证据。停止失败、停止后仍在运行或状态无法读取时保留原分配并续租；只有宿主确认已结束后才允许回收。通知按员工和任务隔离，节点不清理其他节点的告警。已经采集或正在读取的结果按原 delivery 完成持久化和自动收尾，不能因为宿主 idle 或租约过期而丢弃；旧 delivery 的结果不会保护新的执行批次。

故障回归在同一派工接口注入停止响应丢失、仍在运行、未知状态和查询异常。旧实现六项测试中五项失败；修复后另覆盖停止与结果采集竞态、重启后待收尾批次保护。线上不注入供应商故障，采用真实工作任务与独立复核检查自动生命周期。

## v0.11.9 复核成果交接

生产验收发现，执行端虽已保存最终成果并自动送审，QA 的 `task.md` 却只有需求和验收标准。QA 独立测试通过后仍因缺少对应成果报告而正确报告受阻。

复核领取现在在有界历史之外固定读取本任务最新 `submit` / `owner_submit`，去重后将完整成果写入 `task.md`，保留提交者、时间和原文中的产物位置。老板派工快照复用同一正文。执行岗的任务正文保持简洁，员工无需调用公司命令查历史或补交接。缺失或截断的旧快照明确标示不完整，不能冒充完整成果。

回归在真实公司 fork 上先复现缺失，再验证执行、自动送审、复核文件及独立验收完整链路，并用超过历史窗口的后续审计验证最新成果不会被挤掉。原始失败记录保留，生产受阻任务在升级后恢复复核阶段，不以人工批准代替 QA。

## v0.13.28 结果读取有界

回合结束后，执行端按 10 秒起、最长 60 秒的退避读取本轮最终答复，共 20 次，窗口约 17 分钟。读取只取该回合展示顺序的最后一条答复。工具调用即使在答复之后才结束，也按首次出现的位置排列，不会被误判为答复尚未就绪。

任一次读到非空答复即按正常结果送审，短暂迟到不影响结果。窗口耗尽仍读不到，执行端提交受阻结果，正文写明连续读取失败的原因。受阻不推断成功，也不自动通过；执行记录、工作树与已有提交保持不变，老板核对会话后可恢复任务。

`runtime_execution.error` 记录 `runtime_result_unavailable:<原因>`。原因为 `channel_unavailable`、`timeline_unavailable`、`still_active`、`not_yet_available`、`not_found` 或 `read_failed` 之一，说明最后一次读取失败的类别。受阻提交失败时保留同一幂等键，恢复后重放。

## v0.13.38 收尾边界

宿主快照可能在回合内工具仍运行时短暂报 `idle` / `activeTurn` 为空，回合结束事件也可能在供应商后续段落之前到达。v0.13.38 起，回合终态不再以快照为准：该回合围栏内任何 `status: running` 的工具调用（或进行中的压缩）都判为回合未结束，按 `still_active` 继续有界读取；工具行可能因按首次出现位置固定而翻到靠前页，读取会继续分页扫过本回合的全部行。

读到文本答复也不直接等于交付：代码任务的答复必须声明单独一行 `提交：<40位SHA>` 或首行 `工作结果：受阻`，复核答复必须声明 `复核结论：通过/退回` 或受阻结论，否则按 `not_yet_available` 继续等待，不再用工作树 HEAD 补齐送审、也不会因复核结论未出现而提前受阻。门禁对全部运行时文本来源生效：持久时间线读出的答复与结束事件携带的文本（原生宿主唯一结果来源）同样适用。窗口内同一回合补出的真正终稿按声明的 SHA 正常送审一次，SHA、PR 头与 CI 证据与实际终稿一致；窗口耗尽仍无合格答复转为可恢复受阻。非代码任务的散文答复与结构化成果通道保持不变，不读取其他回合或跨任务的结果。

收尾单飞：同一执行批次同一时刻只有一个收集通道。并发的结束事件与定时重试共享磁盘上的执行行，每个通道在读取完成后与提交前重读该行；行已不在 `collecting`（已结算、中断或被接手）则放弃写回，磁盘行已结算的不再提交。同一成果因此只送审一次。
