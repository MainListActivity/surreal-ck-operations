# 公司任务 MCP 服务独立验收准备（#26）

状态：**测试设计已准备，未执行服务验收**。基线为 operations `0d32afbc732c38d2a14193ff46c2af75647296c6` 的 #23—#28 契约；#24 核心与 #25 适配器的最终接口、实现提交和运行实例尚待交接。此文件供 #27 集成复核与 #28 最终独立验收使用。#26 通过只表示矩阵、输入及证据格式可供执行。

## 固定范围与执行门槛

- 待验对象必须记录 #24、#25、#27 各自经独立复核的提交、最终集成提交、`pnpm-lock.yaml` 哈希、SurrealDB 引擎/SDK 版本、官方 MCP SDK 版本、进程管理方式和服务监听地址。只对固定集成版本给出通过结论；变更后重跑受影响用例。
- 连接目标须是本服务独立 namespace/database，首选 `sck_agent_company/control_plane`。先由工程提交同名归属检查和 bootstrap 前后对象清单；如同名已有无关数据，停止写入并记录实际选择，不清理或覆盖。客户/产品 namespace/database 的基线对象计数与代表性只读指纹由工程在授权环境脱敏提供，QA 在执行前后独立比对；不在报告中列出凭证、客户记录或连接密文。
- 只对本服务管理的新合成任务做写入和 GitHub 投影；旧 #2、#17—#28 仍由 `scripts/queue.py` 与原 Issue 负责。不能把旧任务作为破坏性测试输入。测试进程仅连接 `127.0.0.1` 上工程交接的实际端口，且不会以健康检查代替 MCP tool 调用。
- #27 交付后，QA 用自己的受控凭证运行独立客户端。至少另一位 **真实现有员工**在自己的会话、使用自己的独立凭证亲自完成 MCP 领取与提交；QA 再以 qa-01 身份独立验收。员工身份须从服务端凭证记录和审计事件核对，Paseo 会话 ID 只作为交接归因，不是服务凭证。不能让一位操作者轮换 token 冒充两位员工。
- 服务最终需由工程可维护的本机进程管理保持运行；QA 验收结束再确认 ready 和进程状态。启动、停止、重启只作用于本服务；不操作其他应用或产品数据。

## 合成输入与夹具

使用本服务的管理员受控入口创建一个带运行批次标识 `qa28-<UTC时间>-<随机后缀>` 的测试上下文。标识仅用于查找和清理建议，不当作权限凭证。管理员先建立两个或更多同岗位合成任务 `A`、`B`，一个需要 qa 验收；另设依赖、阻塞、撤销、版本冲突测试任务。正文只写合成文本，例如“验收演示 A，无客户数据”。员工实体使用已登记的 qa-01 与由经理唤醒的一位现有不同员工；错误凭证、撤销后的凭证和无权限岗位是额外负例。完整凭证只存于本机权限受限文件，由 #27 交接安全路径；测试日志仅出现不可逆指纹末段或 `credential_ref`，禁止打印 token。

每个变更请求记录唯一 `request_id`。重复重试使用相同 `request_id` 与相同 payload；冲突用同一键及仅改变一个业务字段的 payload。并发领取使用两个独立客户端连接、同一任务版本及受控起跑屏障；先验证两个请求确实重叠，再观察服务和 DB 终态。租约测试使用服务端时间、可配置短 TTL 或受控时钟；客户端本地改时钟不能成为过期证据。旧 fencing 值、错误任务版本和旧员工凭证分别保存为只读测试输入。故障注入仅作用于 GitHub 适配器/网络代理或隔离 outbox worker，不删除 outbox、不篡改业务记录；记录注入开始/结束和恢复方式。

在执行前确定清理策略：优先保留带批次标识的测试任务与审计链供复核，并按服务的正式撤销/归档接口收口；不得直接删真实队列数据。任何脚本不得输出 `.env`、root、员工 token、GitHub PAT 或原始客户资料。

## 验收矩阵

`E2E` 表示必须经过运行中的官方 MCP 客户端、实际服务与真实目标 SurrealDB；`故障` 表示在真实持久服务上对依赖做受控故障注入；`静态` 只能补充证据，不能替代 E2E。每项均保存操作前后脱敏状态、命令及退出码、请求相关 ID、审计/outbox 序号与 UTC 时间；拒绝项还要确认没有目标外副作用。

| ID | 类型 | 输入／操作 | 可观察的通过条件 |
| --- | --- | --- | --- |
| B01 | E2E | 对实际 loopback URL 用官方 SDK 客户端 initialize、tools/list；分别无凭证、正确凭证、错误凭证调用受保护 tool | 握手和列举符合最终公开契约；正确凭证可执行，缺失/错误凭证被拒绝；无密钥返回；Host/Origin 异常请求按冻结的 HTTP 策略拒绝。 |
| B02 | E2E | qa-01 `get_context`；允许岗位创建合成任务与上下文；员工尝试管理员管理入口、自授角色或跨岗位操作 | 上下文只含该身份可见任务；员工不能自授角色/任意创建管理员；未授权写请求拒绝且 DB 审计无成功写。 |
| B03 | E2E | 两个独立客户端同时 `claim_next` 同一任务 A；同岗不同员工分别领取任务 A/B | A 恰有一个有效领取人/租约/fence，另一方收到可辨的无可领或冲突结果；A/B 可由两人各领一项，不出现重复 owner。 |
| B04 | E2E | 有效领取者 `heartbeat` 续租并 checkpoint；等待服务端租约超时后由获准者重新领取；旧执行者携旧 fence 尝试 heartbeat/checkpoint/submit | 续租仅在当前租约有效时延长；新领取产生更高/不同 fence；旧 fence 三类写入均拒绝，成果及审计不被旧执行者覆盖。 |
| B05 | E2E | 用同一任务版本和相同幂等键重复 submit；再用相同键、不同 payload 提交；另用陈旧版本提交 | 相同请求只产生一份交付、一条有效状态迁移及一个逻辑 outbox 事件；payload 冲突与旧版本明确拒绝，原成果不变。响应丢失重试也需检查 DB 终态。 |
| B06 | E2E | 员工提交 A；提交者使用新会话或新凭证尝试 review/accept/return；独立 QA 用本人凭证 review，并按授权 accept 或 return | 服务端按稳定员工身份禁止自验，换会话/换凭证不绕过；独立验收能完成规定转换，签名与审计员工 ID 各自正确。 |
| B07 | E2E | 管理员撤销员工凭证/角色或任务授权；旧 token/已建立连接继续调用 get_context、claim、heartbeat、submit；错误/不存在身份尝试调用 | 撤销在冻结的生效边界内阻断后续受保护操作，既有租约处理按明确规则执行；错误身份不得借 `employee_id` 参数冒名，DB 终态无越权修改。 |
| B08 | E2E | 任务阻塞→按授权恢复、依赖任务验收→解锁下游；对已撤销任务尝试领取/提交 | 状态和依赖仅按业务契约变化；撤销后无新领取或交付，已有租约按定义失效；错误请求不误解锁。 |
| B09 | E2E | 有活动任务、checkpoint、提交、凭证和 outbox 时用正式命令重启本服务，再重新 initialize/get_context；重复 bootstrap | 任务/员工/审计/交付保持；旧客户端重新鉴权；租约按服务端时间恢复或到期，不复活旧 fence；bootstrap 不重置数据或重复生成凭证/任务。服务重启后仍 ready。 |
| B10 | 故障 + E2E | 暂停 GitHub 投影/注入超时、提交本服务新任务，然后恢复 worker；模拟“GitHub 已接收、响应丢失”再重试 | 业务提交先在 DB 持久完成；outbox 待处理可观察，恢复后原 GitHub 新任务看板仅一份逻辑成果，稳定幂等标记相同，重试不会重复评论/错误关闭。失败不投影到旧 v2 Issue。 |
| B11 | E2E + 静态 | 对比目标库和非目标客户/产品库的前后只读指纹/对象计数；检查服务绑定地址、日志与提交内容 | 仅目标 ns/db 有预期合成写入；非目标库指纹无变化；服务只监听 loopback；日志、Issue、提交和 MCP 响应无 root、员工 token、PAT 或 `.env` 内容。只查脱敏存在性/指纹，不展示原始秘密。 |
| B12 | E2E | 第二位真实员工亲自用 MCP 客户端领取→heartbeat/checkpoint→submit 合成任务；qa-01 在独立会话和独立凭证下领取 review→验收 | 客户端实际发送 initialize、tools/list、各 tool call；服务审计/DB/Issue 投影分别归因两位真实员工，验收人不是提交人；请求和结果可由两位各自回执交叉核对。 |

## 证据包格式

每一执行批次在 #28 原 Issue 提交一份索引；原始脱敏日志放授权的本机证据目录，不将员工 token、root 连接配置或客户记录上传。推荐表格列：`case_id | 结果(PASS/FAIL/BLOCKED/NOT_RUN) | 输入任务/员工代号 | 请求/状态版本/fence(脱敏) | UTC 起止 | 客户端命令与退出码 | DB 前后摘要 | MCP 响应摘要 | 审计/outbox/投影 ID | 日志引用 | 限制/缺陷 Issue`。所有测试先记 `NOT_RUN`，不得把工程单测通过转写为 QA E2E 通过。

缺陷记录固定包含：集成提交、最小合成输入、预期/实际、重现命令、首个失败断言、请求 ID、脱敏响应、DB 前后状态、是否可重试与恢复位置。若负例产生越权写入或非目标库变化，立即停止后续写测试，保留证据、交 #27 工程返工；修复后固定新提交并重测相应矩阵。`BLOCKED` 必须给出缺失的接口、环境或真实员工输入及解锁条件，不写成 PASS。
