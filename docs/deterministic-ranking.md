# 确定性模型排序 v1

仅自动维护 sck-haiku、sck-sonnet。模型排序不调用 JEV；新模型身份映射原有裁决流程不在本次范围。Opus/Fable 成员、顺序及组内配置保持人工维护。

排序先分安全层：正常、首 token >20000ms、所有已知账号最紧窗口剩余为0、持续报错。20秒本身不置后，人工置顶只在同一安全层优先，不能越过限制。额度没有模型窗口归属信息时是供应商层保守风险提示，保留成员作为末尾后备，最终按模型的限额、熔断和可用性由 Magpie 执行；不声称每个模型都被硬封。任一账号未知时不声明全部耗尽，多个账号取可用最佳余量。低余额仅展示风险，具体账号的90%/耗尽层由原生 PACE 管理。未知额度、未知计费类型和未知延迟均不当作0或已测充足。

每层优先 Magpie 明确返回 subscription/plan 的账号；计费未知次之，明确 API 计费最后。免费价格不推断订阅。各计费层按 AA 分降序从最高分起构造能力档：该档最高分与模型分差 <=2 的归一档；下一模型再开新档。这样不存在非传递的两两“相差2分”比较器。档内严格按首 token 延迟升序，然后输出速度降序、已验收任务绩效降序、AA精确分降序、额度/重置时间的消耗节奏降序，最后保留原顺序。绩效只沿用完整任务验收后的既有评分。

延迟与输出速度优先使用15分钟内新鲜且样本足够的EWMA，其次新鲜单次值，再回落到 Magpie 原生7天平均；来源显式展示。未知延迟在同档已测延迟之后，不能伪装为0。20秒置后与档内比较使用同一实际采用值，不混用不同口径。额度重置时间与 kind 保留，但账号名匿名化；错误读取或已过重置时间的窗口不延用为已知余额。

公司把模型顺序写入 Magpie 的 order 分组。本机参与这些自动组的供应商，通过官方 provider set routing=pace 使用原生账号 PACE，变更前的路由策略只记ID/策略到服务目录 model-routing/account-routing.json，恢复发布版本不会自动撤回此配置，可按记录显式恢复。因供应商是共享实体，其他使用该供应商的会话也使用这个账号策略；不修改手动组配置。remote-magpie 仅设置本机中继的账号策略，远端内部账号由远端的配置管理，不能冒充已设置远端 PACE。

刷新仍为请求驱动、后台单飞和2/5/10分钟间隔。保存只改变间隔并重置时钟，旧自然语言不再参与计算；当前生效规则只读展示。置顶立即获取观测并按同一规则计算。成功记录包含固定规则引擎版本、完整观测和每模型 decision；不生成虚假JEV分数。刷新或采集失败保留旧顺序，陈旧刷新不得覆盖保存/置顶后的结果。
