# 确定性模型排序 v2

仅自动维护 sck-haiku、sck-sonnet，排序不调用 JEV。Opus/Fable 的成员、顺序及组内配置继续人工维护；新模型身份映射保留已有裁决流程。

排序依次执行：安全层、新模型试用、AA能力档、计费层、层内置顶、加权分。正常模型优先，首 token >20000ms、已知账号全部耗尽、该模型持续报错依次置后；20秒本身不置后。模型故障按完整供应商/模型ID读取 Magpie 路由尝试，不把一个模型的错误扩展到供应商的其他模型。人工分类、置顶与任何权重都不能跨安全层。

没有原生请求记录且没有路由尝试记录的新模型优先试用，不要求先有延迟数据；有过失败尝试的模型不会继续冒充新模型。安全限制仍优先。存在试用候选时，下一次请求最早30秒后触发后台重新采集；取得请求记录后退出试用优先级，没有待试用候选后恢复2/5/10分钟配置。不是定时合成模型请求，不产生额外的探测推理费。原生用量读取失败会使整次采集失败并保留旧顺序，不把读取失败伪装为无数据。

每个安全层按AA降序从最高分构造能力档，档顶与成员分差不超过配置宽度（默认2，允许0–10），下一模型开新档。AA未知单独在已知档之后。新模型试用是明确的探索例外，可以先于更强的已测模型取得观测。

每档内免费 → 套餐/积分覆盖 → 计费未知 → 额外付费。Magpie明确免费标记用于识别免费，subscription/plan仅作为套餐覆盖的默认估计，不保证该供应商每个模型都包含在套餐内。可以按完整模型ID手动修正这四种分类或恢复自动；额外购买的积分不自动视为套餐内免费额度。分类修正影响排名，不改变供应商真实计费、余额或可用性。

## 层内公式与默认权重

综合分 = 100 × Σ(权重 × 指标得分) / Σ权重。每项权重0–100且至少一项大于0。固定参考尺度防止加入候选时其他模型的得分一起改变，所有未知指标保留未知且不加分，不重新分摊其权重。

| 指标 | 默认权重 | 0–1指标得分 |
| --- | ---: | --- |
| 额度消耗紧迫度 | 35 | p/(p+1)，p为剩余百分比/距重置小时数 |
| 首token延迟 | 30 | max(0,1−延迟毫秒/20000) |
| AA能力 | 15 | AA分/100，限制在0–1 |
| 输出速度 | 10 | tokens/s ÷ (tokens/s+50) |
| 完整任务验收绩效 | 5 | 绩效分/5，限制在0–1 |
| 预计费用 | 5 | 1/(1+估算费用) |

套餐覆盖和免费层预计额外费用为0。额外付费模型按每百万输入token（其中实际缓存命中率对应缓存价格）加每百万输出token估算，固定输入:输出=1:1；价格或缓存数据缺失不计算费用得分。此项是统一比较口径，不是实际账单预测。层级中的免费/套餐优先是硬规则，不另设在同层恒定的无效权重。

额度紧迫度是公司跨模型排序的估计：每账号取最长有效重置窗口，模型使用可用账号中的最大节奏；并非完整复刻Magpie的模型专属窗口、低余额层或远端内部账号决策。余额仍是供应商层保守观测，任一账号未知时不声称全部耗尽；Magpie原生免费标记的模型不因不消耗的套餐余额为0而置后。原生账号路由最终决定哪个账号能实际使用该模型。

延迟与输出速度优先使用15分钟内样本足够的EWMA，其次新鲜单次值，再回落原生7天平均。所有计算、快照和预览使用同一函数；结果保存policy、每项归一值/权重/贡献、综合分、试用状态及决策原因。历史quality-pace-v1仍可读，不伪装为JEV评分。

## 配置与预览

Paseo与老板网页均提供权重、能力档宽度、恢复默认权重和逐模型计费分类。编辑后自动使用固定观测预览顺序、线上原名次和各项贡献，保存前不修改线上分组。更新观测显式重新读取Magpie；自动预览不会反复读取供应商额度或发起模型推理。观测不完整则报错，不生成假预览。观测时间在预览中明确展示。

保存持久化到company_meta:model_routing.ranking_policy，不需数据库迁移；旧配置缺少该字段时使用默认值，旧客户端只改刷新间隔不会重置权重。保存使在途旧刷新失效，下一次员工请求触发新排序。正常刷新无独立定时器。页面15秒轮询只更新展示，不等于排序刷新。

公司将计算出的模型顺序写入Magpie的order分组；参与自动组的本机供应商仍以官方provider set routing=pace选择内部账号，原值保存在服务目录model-routing/account-routing.json。remote-magpie只控制本机中继账号，远端内部账号由远端配置管理。升级不会改变Opus/Fable配置。恢复旧版本不会自动撤回原生PACE配置，可按备份显式恢复。

## 页面分层解释

两端列表保留Magpie当前顺序，按安全状态、试用状态、AA档和计费类型四个条件标出层边界。每层标注名次范围、成员数量，以及该次快照的AA范围、档顶与档宽；同层置顶先排，其余层内分降序，跨层不比分数。可展开查看各条件的形成方式。档位范围使用完整排序快照中的成员计算，移除成员或修改待生效配置不会篡改旧快照的解释；无排序决策的新成员标记待分层。手动顺序将同层拆开时沿用同一层号并标记续，不重排列表。
