# 实现人绑定、独立复核与无法派工（SYS-DISP）

本文件说明工程任务的执行与复核规则、无法派工的可视化，以及经理接手与只读核对的操作方法。规则在核心（`src/core.ts`）、
调度器（`src/dispatcher/dispatcher.ts`）和推导模块（`src/contributors.ts`）中强制执行，提示词与偏好只作说明。

## 一、规则

- **作者**：提交过任务的人，或持有过执行阶段租约的人（认领、检查点、阻塞、释放）。作者身份永久保留，退回、撤销或改派都不会移除它。
- **复核人**：在复核阶段持有过任务、且不是作者或实现人的人。复核、退回、验收都不会使其成为作者，它可以重复复核，但不能实现。
- **实现人**：首次执行阶段认领时绑定（`task.implementer`）。退回默认回到实现人修复，保留其登记分支与现场。
- **独立复核**：`accept`、`return` 与复核阶段的认领，对全部作者与实现人一律拒绝，不只看最后一次提交人。
- **开放租约**：当前持有人的租约若尚无决定动作，其行按任务当前阶段计（复核阶段计为复核人）。这保证复核人能完成自己的复核。
- **历史不清**：旧行缺少阶段且之后没有可判定的决定动作，按作者处理（fail-closed），并在结论中列出该行数量。
- **并发**：推导视图与任务版本同读于一个事务。租约写入在 SQL 内比对版本，视图已变则重读重试；连续失败返回 `conflict`，不写租约。

## 二、经理接手（`implementer_takeover`）

仅 gm 可用，需要 `manage` 能力。条件与写入都在一个比较并交换的事务里完成：

- 任务处于执行阶段（`ready`、`doing`、`blocked`），`expectedVersion` 与当前版本一致；
- 目标员工具备执行能力、岗位与轨匹配；若目标是当前复核人，必须同时指定独立的 `replacementReviewer`，且它不是任何作者；
- 理由不少于 8 个字符，幂等键相同且载荷相同则返回原结果；
- 写入审计、出站事件与幂等记录；原持有人的租约被撤销（围栏前进），作者记录不被删除。

接手不是老板批准，也不替代上线决定。需要花钱、扩编或换供应商的事项，仍须经老板或经理按既有流程处理。

## 三、只读核对（`contributor_dryrun`）

仅 gm 可用。输入至多 20 个任务号，输出每个任务的状态、版本、当前持有人、上次提交人、作者、复核人、已排除的人、
实现人状态（`bound`、`proposal`、`manager_decision`、`fresh`）、建议（只建议，不写入）与逐事件时间线（每行的角色与阶段来源）。
它不改变租约、提交人、老板门、历史或实现人。

## 四、无法派工的可视化

同一评估器（`src/dispatcher/dispatch-blocked.ts`）产生调度器、通知、花名册、队列与目标卡的结论。每个结论包含：

- 任务、目标、阶段（执行或复核）、`checkedAt`、等待起点与已等待分钟数、可派工候选数；
- 全部生效的原因码、涉及的候选、负责岗位（gm 或老板）、恢复动作与下一触发条件；
- 材料性阻塞（无独立候选、作者回避、实现人冲突、状态未知）即时通知；可自行恢复的等待满 5 分钟通知。

通知键为 `dispatch-blocked:<任务号>:<阶段>`，同一阶段的重复 tick 与重启只保留一条未解决项，条件变化时更新文本。
可派工后自动消警（通知记录写入 `resolved_at`）。目标卡显示根阻点，展开可看全部原因、候选与恢复动作。

状态未取得时只能是 `unknown`，不会显示为忙碌。花名册与队列的会话状态来自本轮 tick 的观测，不再二次读取 Paseo。

## 五、QA 验证（入口 → 操作 → 应见）

以下步骤在公司 fork 的隔离库或受控测试接缝上执行。生产只读核对不得造数，也不得改动任务。

1. 目标卡：打开一个存在无法派工任务的目标 → 应见根阻点一行，写明阶段、原因与已等待时长；展开后应见每条原因、候选与恢复动作。
2. 花名册：有空闲会话、但 tick 观测为忙碌的候选 → 应显示忙碌，不显示异常，且与调度器的判定一致。
3. 复核接力：工程 A 实现并提交 → 工程 B 复核并退回 → 应见任务回到执行阶段、实现人仍为 A；B 不能认领执行。
4. 作者回避：A、B 皆为作者 → 工程 C 复核可认领；A 与 B 认领复核均被拒绝（`self_review`）。
5. 经理接手：gm 对执行中的任务调用 `implementer_takeover`，理由不足或版本过期 → 被拒绝；理由充分且版本一致 → 实现人变更，原持有人租约被撤销。
6. 只读核对：gm 调用 `contributor_dryrun` → 返回作者、复核人与时间线，前后任务版本与审计行数不变；非 gm 调用 → `forbidden`。
7. 通知去重：同一阶段连续 10 次 tick → 同一通知键仅一条未解决项。

## 六、未覆盖与限制

- 10 次重复 tick 的端到端去重仅有通知键的单元用例，未在真实调度循环上重放。
- 目标卡的“影响 N 项后续”未计算，当前只显示同目标内其它阻塞项数。
- 历史行缺阶段时，无法判定的行按作者处理，会使任务进入 `manager_decision`，需经理接手。
- 扩编（如临时增加一个工程席位）与额度决定属于经理与老板，不由本规则自动完成。
