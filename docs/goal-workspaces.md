# 工程、目标与会话

公司调度创建的 Paseo Project 以真实仓库的规范路径去重。Workspace 以仓库与目标 ID 去重，标题显示目标名称和 ID；没有目标的工作进入同工程的“日常维护”。跨仓库目标在各自工程下建立 Workspace，保留相同目标 ID。

员工会话启动于仓库 root，私有通信目录仍逐实例隔离。每轮先读私有 claim.json，再按其中登记的 worktree、分支和写权执行；root 不是代码提交现场。工作树仍由任务服务在领取时分配，员工不能创建工作树。会话的目标绑定同时在派工候选池与服务端领取事务中校验。此约束限制任务领取，不是对原生文件和 shell 工具新增操作系统沙箱。

老板按依赖关系拆任务；调度器只派发依赖满足的工作，并继续检查写范围、资源上限与独立审核容量。独占工作树按任务或 lane 分配，串行任务复用 lane；回收仍要求无活动和返工引用、工作线完成、无脏改动。并行数下降不直接触发强删。

目标会话不再因闲置、唤醒次数或上下文阈值被自动归档。实际模型配置仍可就地校准；会话失效时撤销员工身份，但保留其在目标下的会话记录。显式归档目标 Workspace 会连带归档会话，因此现场回收不能调用目标 Workspace 归档。保留会话不代表主机能无限运行进程，现有内存与全局运行数门禁继续生效。

迁移仅新增 employee.workspace_scope 字段，不重写旧员工、任务、租约、fence、工作树或历史。运行中的旧会话保持原绑定，允许接续已绑定或已领取任务；新任务使用新布局。旧会话按原安全门禁结束，旧列表的清理只归档没有活动会话的旧入口，保留目录与历史。不批量搬迁在途 Agent。

发布守卫要求目标核心与插件 vendor 同时具备目标会话契约；缺少 workspace_scope 领取检查的旧版本会在任何切换副作用之前被拒绝。上线后保留当前健康版本并以前向修复恢复，不允许回滚到会跨目标复用新会话的旧调度器。
