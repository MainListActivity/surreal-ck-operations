# 外部 AI 员工接入：v3 设计提案

> 历史记录：本文档记录 0.7.0 之前的设计与状态，已被 0.7.0 取代。正文中的 MCP、`active`、`releases/` 等描述不再适用，仅供追溯。

状态：Proposed，尚未实现或部署。适用于用户自建 agent、其他模型平台和远程机器加入现有 AI 公司。当前已运行的仍是 v2 本机队列。

## 决策

建设一个独立的公司任务控制服务，提供同一套任务操作的 HTTP Interface 和 MCP Adapter。员工无需采用同一模型、框架或聊天工具。GitHub 保留为人工看板、成果引用和代码评审入口；迁移完成后，任务状态、身份、租约和验收决定以控制服务为唯一事实来源。

沿用 TypeScript / Bun / Hono 的团队技术栈，部署在内部运营域，不塞入客户产品的浏览器直连、workspace 数据访问或虚拟员工身份链。存储必须实现事务性领取、唯一幂等键、版本条件更新与持久 outbox；实际数据库实现须通过同一契约测试再确定，不以进程内互斥代替数据库原子性。

## 当前 v2 的具体限制

- registry 仅把 employee_id 与调用方自行传入的 agent_id 比较，不是对远程调用者的认证。知道别人的 ID 不能被当作获得身份。
- fcntl 与 .runtime/leases.json 只协调本机同一 checkout；复制目录或换机器即不再共享锁。
- 员工共用 gh 凭证，规则是协作纪律，不能强制防止外部 agent 绕过队列修改 GitHub。
- 唤醒绑定 Paseo 会话。其他运行器需要 Adapter，模型额度不足属于运行器故障而不是业务验收失败。
- 定时巡检实际出现额度失败与重复触发；不能依赖 LLM 轮询保证租约、到期、重试和通知。

## 身份与入职

身份分四层：认证主体 principal_id → 稳定员工 employee_id → 服务端授予的岗位与能力 → 每次执行 run_id。runtime_ref（如 Paseo 会话 ID）只用于定位进程，不作为认证凭据。

管理员创建待入职员工，固定所属公司、岗位、能力、可接触的项目/资料、并发额度及有效期。自建 agent 用一次性 enrollment grant 证明它持有被授予的接入资格；登记其公钥或工作负载身份，换取面向任务服务的短期访问凭证。具体生产凭证配置不进入 Issue、聊天记录或代码。

接入主体只能声明自己支持什么工具，不能自己给自己授予岗位或审批权限。老板可以在预先批准的用人和权限范围内配置岗位；增加敏感数据、对外发送、付款或生产权限另走 owner 决策。撤销员工立即禁止新任务，已有运行的续租和写入也按撤销策略失效。

员工读取岗位包与版本、完成一张合成入职任务，通过验收后 active。岗位包包括职责、任务来源、输出格式、验收、失败/升级路径；不要求员工加载整个公司历史。

## 员工最小 Interface

| 操作 | 输入和服务端保证 |
|---|---|
| get_context | 从已认证身份推导员工，返回岗位包、授权、资料范围及协议版本 |
| claim_next | 按授权岗位、能力和容量原子领取一个 ready 或 review；可指定候选任务，但最终由服务端检查；返回任务包、lease、fencing_version、expires_at |
| heartbeat | 校验当前租约及 fencing_version，续租并记录 checkpoint；撤销/过期的运行不能续租 |
| submit | 提交不可变成果版本、证据引用、输入版本、限制及幂等键；核对租约，转独立验收队列 |
| report_blocker | 保存上下文和恢复点，分类为需要人、工具权限、临时错误或运行器不可用；按策略释放或冻结租约 |
| review | 领取的是验收任务；对精确成果版本提交通过/退回；原贡献员工及其别名身份不能自验，重新提交使旧版本验收失效 |

所有变更有 expected_version 和 idempotency_key；相同键不同请求内容应冲突，而不是静默返回旧结果。服务端决定调用者身份、岗位和权限；请求中的 employee_id 只可作为诊断信息，不能选取其他身份。

CLI 变为 HTTP 客户端，保持 queue/claim/submit 等员工体验。支持 MCP 的自建 agent 用相同动作工具；只有 HTTP 能力的 agent 用薄 SDK 即可。HTTP/MCP 共享同一个领域 Module，不能各自实现状态机。

## 两种运行器 Adapter

1. 托管唤醒：Paseo Adapter 根据持久 outbox 通知，启动或恢复已有员工会话。适用现有员工。
2. 自主拉取：自建 agent 的 worker 循环从任务服务长轮询/按退避拉取 claim_next，无需老板远程启动它。worker 在模型之外续租、持久 checkpoint 和报告运行故障；进程崩溃由服务端租约处理。

外部 agent 最小循环：认证 → 读取岗位包 → 领取 → 心跳/执行 → 提交成果或阻塞 → 等待下一项。通知只用于加速，离线恢复从任务事实查询；重放通知不等于再执行一次工作。

## 同岗多人和掉线接管

同岗位可有多个独立员工，每个员工可有不同运行器；服务端原子领取防止同任务重复分配。拆分父目标为子任务，固定接口、写入范围、基线和集成负责人；代码员工按 claim 持久登记用工作目录（串行可共享物理树，每项独立 task 分支；并行写手由调度隔离），成果以提交/补丁哈希交付，集成人交固定候选版本供 QA 验收。

租约到期可按策略重派，但每次重派增加 fencing_version，旧 worker 即使恢复也不能再提交或改状态。外部副作用也必须通过受控工具入口检查版本和幂等键；仅给提交加锁并不能撤销旧 worker 已发出的邮件、支付或 Git push。首期因此默认仅接内部分析与产物生成，敏感副作用仍走独立批准与网关。

执行者换模型/会话，employee_id 及贡献记录仍保留；不能借新编号规避独立复核。身份同源的别名由管理员登记，初版至少阻止同一 employee/principal 及该版本贡献者自验，不宣称能自动识别所有未申报身份关联。

## 持久调度、运行故障与 owner 队列

用普通后台进程处理到期、重试、依赖解锁和 outbox，不需要每轮消耗 LLM 才能判断队列是否有任务。业务优先级与验收判断仍由公司内受权岗位处理（复核岗验收、老板拍板）。

模型额度不足、限流、鉴权失败分成不同错误。额度不足将对应 runtime 标为 unavailable，保存 checkpoint、退避并合并通知；在已有岗位/资料/预算授权范围内才能转给另一个合格运行器。不得因此跳过验收、扩大数据授权、自动充值或无限重试。

owner 只接真实客户、外部顾问、不可替代的资料及关键决策。人工决定须由独立真人认证入口或可靠记录的用户会话作出，不能因所有 agent 共用的 GitHub 账号写了“批准”就视为真人授权。系统将问题归并进老板待办，回答与任务版本绑定，超期不推定同意。

## GitHub 与资料

控制服务持有 GitHub App 的受限安装权限，外部员工不拿公司 PAT 或数据库 root。任务事件在事务中写入 outbox，再异步投影到 Issue；失败显示同步待处理，重试不会重复评论。GitHub 上手工关闭/改标签是请求或投影漂移，不能绕过状态机直接放行后续。

代码仍以 Git PR/固定提交为成果；原始客户资料通过任务授权的受控资料引用提供。外部 agent 不默认读取整个私有运营仓库或全部客户资料。投影到公开产品仓库的内容必须是可公开技术信息。

## 分阶段交付及验收

| 阶段 | 交付 | 必须通过的验证 |
|---|---|---|
| 1 | 任务核心 + 员工认证 + HTTP worker + 受控资料引用 | 两台机器同时抢一个任务仅一方成功；可领不同任务；冒用员工 ID、越岗位、越任务资料拒绝 |
| 2 | 租约/心跳/checkpoint/幂等/成果版本/独立验收 | 强杀后可恢复；旧租约写入被拒；重复提交一次效果；本人/贡献者不能验自己的版本；撤销立即限制动作 |
| 3 | Paseo Adapter + 自建 worker Adapter + GitHub 投影 | 两类运行器互相交接；GitHub/worker 断网后收敛；重复通知不重复执行；预算故障不无限唤醒 |
| 4 | MCP Adapter + 协议测试包 + 真人决策入口 | 外部 MCP 与 HTTP 走同一权限/状态机；独立 owner 授权；接入者跑完合成入职和验收闭环 |

MVP 先通过两种真实运行器接力完成“领取 → 交付 → 另一员工验收”，再扩大模型、团队与工具种类。现有 GitHub 页面足够作为看板，首期不开发复杂新前端或通用聊天系统。

## 从 v2 迁移

先做只读导入核对，保留 Issue 编号和历史归因。正式切换时暂停新 claim，处理或明确撤销活动租约，导入任务与验收历史，核对状态/版本/归属，再一次性把 v2 CLI 切为 HTTP 客户端；旧脚本退出写入角色。GitHub 从主存储变为投影。回退同样先停止领取并对账，不能同时运行两个可写事实来源。

## 标准依据

- [MCP HTTP 授权](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)：远程 MCP 的授权与资源发现按官方规范实施；公司岗位、租约和验收是本服务另行定义的业务契约，不由 MCP 自动提供。
- [GitHub App 安装认证](https://docs.github.com/en/rest/apps/apps#create-an-installation-access-token-for-an-app)：使用安装访问 token，可按仓库/权限收窄，安装 token 有期限。具体密钥托管与部署配置在实现时单独验收。

这是接入方案，不是已提供的公共 endpoint。外部 agent 的具体接入只需补充运行位置、是否支持 MCP/HTTP、工具权限及是否需要处理代码；不需要向聊天提供凭证。
