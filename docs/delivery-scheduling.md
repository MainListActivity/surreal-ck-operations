# 交付调度与供应商分流

v0.11.8 使用执行端程序决策，不增加模型调度循环，也不要求员工调用生命周期命令。

## 队列规则

只对已满足现有工作流条件的 execute/review 候选排序。依赖、独立复核、权限、资源、当前租约和 dispatch_attempt 屏障仍由原有机制校验。

从 requirement_execution 的实际任务成员关系读取 requirement_approval 不可变快照中的 0–3 优先级（0 最高）。不采信任务标题、tag 或未确认草稿；缺少可靠确认的任务使用普通优先级 2。现有数据没有结构化截止时间，因此不推测 SLA 或日期，也不声称计算完整关键路径。

等待满 30 分钟的候选按进入本阶段的时间先后处理，优先于未满阈值的任何优先级；其余按确认优先级、复核优先、等待时间及 ID 稳定排序。等待开始时间来自 create/dependency_unlocked/submit/return/release/revoke/resume 审计，缺失时使用创建时间。不能读取调度事实时仅停止新派工，已运行任务继续监督。Factory 保留名额沿用同一顺序，不再覆盖交付顺序。

持续进入的新高优先级任务不能无限抢在已老化且具备执行条件的任务前面。该保证不承诺资源不足、权限不符、供应商不可用或前置依赖未完成时的启动时间。不会抢占已有工作。dispatch.scheduling 保存 priority、requirement、revision、等待时间和本次选择原因，可复核依据。

## 有界分流

只接受已终止回合的供应商明确拒绝：现有额度/限流错误，或运行端失败事件中的 502/503/overloaded_error。网络超时、丢失启动响应、未知运行状态不证明请求未执行，不允许据此重新派工。原有 dispatch_attempt 屏障和 delivery/fence 围栏完整保留。

同一任务、同一阶段在 30 分钟窗口内最多三次供应商失败，即首次尝试后最多分流两个其他合格供应商；失败过的供应商在窗口内不能再次接手。到期重新评估，仍受全局供应商健康、权限、独立复核与资源约束。预算按运行端供应商身份统计，不声称能控制 Magpie 内部模型账户重试。

执行端先把明确失败及原租约写入本地结果日志，再在公司库按 employee/delivery/fence 保存 provider_failures，最后调用原有幂等 release。重复回调不重复计数；迟到的新错误证明不能写入不同代际。写库或释放失败保留待收尾记录、续租与屏障，由既有重试周期处理，重启不重发模型请求。老板看板会显示 provider_retry 原因及恢复时间。

## 验证边界

行为测试必须先在旧派工实现上复现：高优需求被普通复核/Factory FIFO 挡住、普通执行任务被新复核插队、失败供应商和第四供应商不受预算限制。公司 fork 用真实任务、claim/release、派工账本验证排序、依赖、预算去重及监督器重建。供应商服务由受控本地替身模拟，不向生产供应商注入故障。

线上验收记录在正式发布后补充，不能以静态检查或测试总数代替。
