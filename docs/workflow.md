# 任务状态与流转 v3

执行细节以 [员工协议](../agents/PROTOCOL.md) 为准。任务存于本机公司任务服务（SurrealDB `sck_agent_company/control_plane`），GitHub Issue 为投影看板。

| 状态 | 含义 | 谁推进 |
|---|---|---|
| ready | 依赖完成，可执行 | 调度器派给执行岗位的空闲员工 |
| doing | 已被领取，持有租约 | 持有租约的员工；会话中断时调度器收回并改派 |
| review | 已提交，等待独立验收 | 验收岗位中非提交者的员工；`reviewerRole=owner` 的关口由老板决定 |
| blocked | 等依赖或老板 | 正式依赖等待（`blocked_to` 为空）完成后按原阶段恢复：执行回 ready，复核回 review；`blocked_to=owner` 进老板待办 |

任务视图的 blocked 行带 `blockedTo` 事实：等老板关口时 `blockedTo=owner`（`resumeState` 记录恢复阶段，复核等待显示原复核岗位，缺失显示 `unknown`）；父链 predecessor 在任务 `parent` 字段。
| done | 验收通过（或老板批准） | 自动解锁后续任务 |

## 目标流程

老板提出目标后，系统按产线创建一个交付任务（软件：engineering 实现+合入发布+生产自验 → qa 生产复验；故事：story-author → qa；视频：concept-design → owner）。需要更多步时老板加任务并用依赖串起来。

中途需要老板拍板的节点建 `kind=gate`、`reviewerRole=owner` 的关口任务。旧的 `create_delivery` 三链交付（实现 → 上线申请 → 合入部署）只是兼容旧数据的遗留入口，新目标不走它。

## 故障接续

调度器每 20 秒检查一次员工会话：

- 会话运行中 → 自动续租。
- 会话报错且错误属于额度/限流 → 该订阅标记为耗尽（冷却 30 分钟起，逐次加倍，最长 6 小时），租约收回并附会话日志作为交接包，改派到其他订阅上的同岗位员工；需要时按员工定义新开实例。
- 会话其他错误或关闭 → 实例退役并撤销凭证，任务同样收回改派。
- 超过 90 分钟无 checkpoint → 中止会话并改派。
- 冷却结束后，该订阅先只接一个探测任务；该员工正常完成一轮后恢复为健康。
- 所有订阅都不可用 → 暂停派工，给老板发一条充值提醒（不重复发送），恢复后自动继续。

## 老板待办

关口、员工提问和系统提醒会弹出 macOS 通知。查看和处理见 [运行手册](agent-operations.md#老板入口)。没有回复的事项一律视为未批准，相关任务保持等待。
