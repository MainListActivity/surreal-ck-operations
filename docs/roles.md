# 岗位、员工与执行会话

用户是唯一真人负责人，负责真实律师用户、外援顾问、关键商业与生产授权。经理及五个业务岗位均是 AI；当前工程岗位配置两位员工。

## 三层绑定

1. **岗位 role**：定义队列和职责，例如 engineering。
2. **员工 employee_id**：稳定身份，例如 eng-01；一个员工当前只绑定一个主岗。换岗由经理先处理未结任务，再修改登记。
3. **执行会话 agent_id**：Paseo 实际会话，可替换。经理先确认旧会话停止，再释放租约、登记替补会话及交接记录。员工编号保留，历史归因保留。

权威登记为 [registry](../agents/registry.json)。GitHub assignee 是访问账号，不是 AI 身份。capabilities 限定队列动作；首版员工共用本机凭证，属于协作规则，不能当成恶意代码隔离。将来跨机器或引入不可信员工时，需要独立凭证、工具权限及服务端原子租约。

## 同岗两位 agent

工程队列可以由 eng-01、eng-02 同时消费不同任务。任务领取在本机互斥锁内完成，一项任务一位执行者；每位员工最多一个活动领取，同岗位总产能可大于一。

同一需求多人协作：经理或产品先建父目标，拆接口/数据、UI、集成与验收子任务，写清接口契约、依赖、写入范围和集成负责人。实现者各用隔离 worktree，先独立交付，再由集成人整合固定版本，QA 验结果。集成不代表全部成果自动通过。

同岗复核：提交后仍可进入 engineering 队列，但领取验收时排除 submitted_by 员工；eng-01 提交的成果只能由 eng-02 或其他适任员工复核。原员工换会话仍不得自验。代码复核、业务验收与真人法律意见各自记录。

## 岗位职责

- gm-01：拆解目标、调度、独立验收、解除依赖、汇总 owner 请求；公司规则与运行器由 QA 独立检查。
- product-01：已实现/已验证能力清单、试点流程、业务验收与客户问题定义。
- eng-01：环境与实现；eng-02：集成边界、技术复核，任务就绪时都可承担实现。
- ai-01：AI、法律内容授权链与评测；专业意见经 owner 转真实顾问。
- qa-01：独立验证、回归、异常恢复与发布建议；不验自己的成果。
- cs-01：客户访谈包、试点材料、获授权反馈分析；实际对外沟通交 owner。

## 入职与恢复

经理创建会话并明确岗位 → 员工读取协议并回执 → 登记真实 ID → 员工从岗位队列领取首项任务 → 独立验收。无需用户为 AI 创建不同 GitHub 人类账号。

同一时期最多三个业务员工活动，经理为第四个；其余会话可闲置保留。没有就绪任务时员工结束本轮。换岗、会话丢失、任务租约过期由经理检查并显式接管，不自动抢占仍在工作的员工。
