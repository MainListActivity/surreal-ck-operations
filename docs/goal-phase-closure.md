# 分阶段目标收口

目标完成以本阶段成果契约、真实最终关口与当前未完成工作共同判定，不等于任务列表全部终态。分阶段迁移不会批准终验，也不会把下一阶段工作当作完成；迁移后重新校验原目标。

已结束的非最终关口任务，其外部依赖是执行历史。依赖仍显示在 graph 中，但后续阶段重新打开或阻塞不会重新打开已验收阶段。当前任务与真正最终关口的未完成、缺失或作废外部依赖仍是缺口。全库存在且已完成的外部任务，即使未绑定 goal，也满足依赖；不能被误称不存在。

裸作废仍不算实现完成。误建后重建的历史工作应核验真实替代任务；QA负例夹具应明确确认其非产品交付性质。老板控制台提供 POST api/goal-retired-resolution，输入 goalId、taskId、goalVersion、taskVersion、disposition（replaced / fixture / excluded）、replacementTaskIds、reason、key。请求沿老板控制台鉴权与Origin校验；调用者不能指定生效actor。

处置只追加审计和outbox，以目标、任务版本CAS防覆盖；原void状态、原依赖和原审批不改写。replaced要求至少一个真实done任务，允许位于其他目标或未绑定目标；fixture不允许携带替代任务。excluded表示已获老板阶段终验认可的取消方案或阶段外协调记录，必须有本目标真实owner终验通过，且不能携带替代任务；它是明确的范围排除，不是实现、上线或采样成功。锚点、未作废任务、非老板调用拒绝。相同key与相同请求幂等，不同内容拒绝。收口事务对所依据的作废记录和替代任务核验状态及版本，并写入并发保护戳，避免跨目标任务同时重开产生写偏差。每次读目标重新核验原任务版本与替代任务状态；替代工作被重开后缺口再次可见。修复后走正常finalize，不移除implementation要求、不生成owner批准或客户证据。

现存首次价值第一阶段的历史关系修正应依据退役审计及重建任务验收：全部作废记录逐项核对：重复/重建工作由真实已完成任务覆盖，QA夹具明确分类；取消方案与第二阶段旧协调门按既有老板阶段终验范围显式排除。第二阶段的采样、成本基线及剩余目标继续独立推进。
